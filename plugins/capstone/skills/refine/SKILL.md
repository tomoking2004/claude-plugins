---
name: refine
description: プロジェクト全体（または指定範囲）を最も美しい確定版へ仕上げる．範囲を媒体に分解して refine プラグインの各スキルへ委譲し，媒体間の継ぎ目を走査する．「プロジェクト全体を完璧にして」「全部洗練して」など，媒体をまたぐ仕上げを求められたときに使う．単一媒体の仕上げは refine プラグインの該当スキルを使う．
---

対象：指定された範囲；無指定ならプロジェクト全ファイル（生成物のみ除く；`.gitignore` 対象も走査し，私的なメモ等は変えてよいかを先に問う）．

## 手順

1. **前提確認**：refine プラグインのスキル（/refine:code 等）が見えなければ，refine プラグインの導入を促して中断する．
2. **分解**：対象を列挙し，媒体ごとに分類する．
3. **委譲**：媒体ごとに，対応する refine プラグインのスキル（媒体スキル）を導入済みスキルの description から選んで発動する——対応を列挙で固定しない（媒体スキルの増減に自動で追従させる）．対応スキルの無い媒体は報告する．並行に走らせるなら，同じファイルを同時に書かせない．
4. **継ぎ目の走査**：媒体スキルが済んだ後，媒体間にまたがる整合を走査する．
   - **名前鎖**：コードの公開名が文書（README・SKILL.md 等）でも一致していることを全件確かめる．
   - **用語統一**：同義語群・表記の規約を全媒体横断で列挙し，揺れを潰す．
   - **事実照合**：文書が語る数値・コマンド・手順をコード・実行結果と突き合わせる．
   - **生成物の追随**：生成物を最終のソースから作り直し，手元の生成物との差分ゼロを確かめる——古い生成物でも満たせる確かめ方にしない．
   - **対になる版**：同じ内容を持つ二つの版（README の使い方と各 description，日英の版等）を並べ，片方にしか無い値は意図か欠落かを言えるまで確定しない．一方を元に作った版も，元とは別に走査する．
   - **写しの波及**：写しの元（正）を直したら，全ての写しを同じ内容に直す．
5. **確定**：書き手の文脈を持たない検査役を立てる——公開・提出の前の全文の読みなら観点（事実照合・目的・言語・本番の読み手）ごとに立て，それ以外は1人が，本番の読み手の観点から順に全観点を通す．意図を渡さず，何をいくつ数えたかを報告させる．全文の読みは美の基準が変わった後と公開・提出の前にそれぞれ1回だけとし，経緯を知らない新しい役に任せる．他の周回（走査と直しの一巡）では，1人が走査を変わった文とその参照先に当てる．目的を定める文書は意図に数えず渡す．検査役の担当から，機械の走査がゼロを返した項目を除く．検査役が製品・ツールの公式文書と照合するのは，それを語る文が変わったときと全文の読みだけとする．検査役のゼロは，確定を差し止める指摘（止める指摘）のゼロを指す——事実の誤り・目的に答えていない・数えられる規則の違反・意味が取れないか二通りに読める・明晰さの欠け（一文に二つの事柄・息が続かない・同じ語の近接・字数合わせで痩せた）．この定義を指示へ写し，読み手の役には本番の読み手が持つものだけを渡す．検査役の指摘には確度（読みの確かさ）を高・中・低で付けさせ，「低」は止めず，書き手が判定して報告へ回す．止める指摘以外は採れるものを採り，残りは報告する．検査役に割った範囲の外で見つけた止める指摘も見送らない．範囲の外の，止める指摘でないものは報告だけして，次の作業へ積まない．指定された対象の外は直さず報告する．周回は3まで；止める指摘が残れば部分の手直しを重ねず，指摘のある単位を丸ごと目的に戻って書き直し，それでも消えなければ上流（方針・割り当て）を疑って問う．直したら，直した媒体を手順3へ，直しに関わる継ぎ目を手順4へ戻し，ゼロを確認してから確定する．委譲先・検査役が戻るまで確定を述べない．報告には確定したものと未確定のもの（理由つき），立てた役と渡した材料（立てられない環境ならその旨），通した媒体・範囲と通さなかったものを並べる．

## 制約

公開挙動は保つ（バグ修正で変わるなら明示）．git は読み込みのみ．判断の割れる箇所は推測せず問う．問い方：調べて届くことは調べ尽くし，ユーザーにしか分からないことだけを最初にまとめて問う．問いには調べた範囲・対象の原文・問う理由・答えで変わることを書き，未確認の前提で選ばせない．対象が一通りに読めるなら問わずにその読みで進め，採った読みを報告に1行載せる．ユーザーの発話が問いの形なら，依頼と読まず問いとして答える．

長い作業の途中で，会話が要約された・同じ欠陥を二度直した・読み直すと直しが消えていた・スキルの定義を読み直さずに書いた，のどれかが起きたら，区切りのよい箇所で止める．続きの状態をファイルに残し，別セッションに貼ればそのまま動く依頼の全文（目的・読むもの・済んだこと・残り・守る決定）を示して，移るよう促す．

## 失敗時

/heal:skill を呼ぶ．
