# キャラクターが働く様子を映す仕組み

Claude（本体）とそのサブエージェント（分身）が処理している間，ドット絵のキャラクターが働く様子をパネルに映す．theater は仕組みだけを持ち，絵はキャラクターのプラグインが持ち寄る．キャラクターを足すときに theater は直さず，仕組みを直すときにキャラクターは直さない．

本書は，キャラクターの加わり方と絵の決まり，役割・眠気・眠りの深さ・並べ方の決まり，絵を画面へ出す仕組みとその限界，確かめ方，残っている作業を定める．仕組みを直すときは本書を先に読み，直したら本書も合わせる．

言葉は次のように使い分ける．キャラクターは絵の持ち主（キツネなど）で，演者はパネルに映る1体（本体か分身）である．パネルに映すキャラクターは一度に1つで，演者はみな，そのキャラクターの絵で映る．`$` は，Claude Code の画面拡張（mod）が Claude Code を操作する窓口である．theater はそこに `$.theater` を足し，キャラクターはそれを呼んで加わる．

## 構成

| 置き場 | 中身 |
| --- | --- |
| `.claude-plugin/plugin.json` | プラグインのマニフェスト |
| `bin/theater-claude-code-only` | プラグインを Claude Code 専用にする印 |
| `hooks/hooks.json` | Claude Code に読み込ませるモジュール（`register.tsx`）を名指す |
| `types/index.d.ts` | `$.theater`・演者たちの状態・キャッシュの寿命の型．キャラクターのプラグインにも配られる契約である |
| `hooks/cast.ts` | 演者たちの状態と見せ方の決まり（役割の切り替え・「呼ぶ」の印・眠気・眠りの深さ・一言の付け替えと切り方・列の片づけ・並べ方・絵を先に取る順と収め方・絵の代え方） |
| `hooks/register.tsx` | `$.theater` を足し，Claude Code の出来事を拾い，パネルを描く |
| `hooks/theater.test.tsx` | `cast.ts` と `register.tsx` の検査 |
| `tools/build.py` | キャラクターの絵を，`sprites/`・アイコン・README のプレビューへ書き出す |

## キャラクター

### 加わり方

キャラクターは1つのプラグインで，次のようにして加わる．

- `plugin.json` の `dependencies` に theater を宣言する（`"dependencies": ["theater@<マーケットプレイスの名前>"]`．名前は，theater を載せるマーケットプレイスの `.claude-plugin/marketplace.json` の `name` である）
- `hooks/hooks.json` が，`hooks/` に置いたモジュールを名指す（`{ "modules": ["./register.ts"] }`）
- そのモジュールが，セッションの開始（`session.start`）で `$.theater.join({ name, title, root })` を呼ぶ．`name` はキャラクターの名前，`title` はパネルの題，`root` は自分の置き場（`$.plugin.root`）である
- `sprites/` に，絵（アニメーション SVG）と一覧（`index.json`）を置く．どちらも theater の `tools/build.py` が作るので（「書き出し」が述べる），手で直さない

モジュールは，次の形で足りる（キツネの `hooks/register.ts` と同じ）．

```ts
import type { Register } from 'claude-code'

export const register: Register = on => {
  on('session.start', async ($, e, next) => {
    await $.theater.join({ name: 'fox', title: 'キツネ', root: $.plugin.root })

    return next(e)
  })
}
```

theater は，加わったキャラクターの名前でコマンド（`/<name>`）を登録し，絵を `root` の下の `sprites/` から読む．キャラクターの側に，パネルの描画や出来事の扱いは書かない．

キャラクターを幾つ入れても，パネルは1枚である．映すのは，ユーザーが最後に `/<name>` で選んだキャラクターである．選んでいないか，選んだキャラクターが加わっていなければ，最初に加わったものを映す．選んだ名前はセッションをまたいで残る．キャラクターが1つも加わっていなければ，何も映さず，パネルも開かない．

### 絵の決まり

- キャンバス：64×64ドットの正方形．整数倍に拡大して表示する
- 時間：100msを1刻みとする．1周の刻みの数はキャラクターが決めるが，そのキャラクターの全ての絵で同じにする
- 止まる姿：絵からアニメーションを外して描くとき（VS Code で動かす数を超えた演者と，デスクトップアプリで動きを減らす設定のとき．「表示」が述べる）は，刻み0の姿が出る．止まった1枚として見せたい姿を，刻み0に描く
- 半透明：半透明のドットは使わない（`tools/build.py` が弾く）
- 色：1枚の絵に使えるのは52色までである．README のプレビューは，並ぶ絵を合わせて255色に収める．確かめ用のプレビュー（全ての絵を並べた1枚．「書き出し」が述べる）は，全ての絵と背景の黒を合わせて256色に収める．超えたら `tools/build.py` がそこで止まる．1枚の絵で止まったときは，何も書き換わらない．プレビューで止まったときは，先に書き出すもの（`sprites/` とアイコン．確かめ用のプレビューで止まったなら README のプレビューも）が書き換わっている
- 大きさ：1枚の SVG は131,072文字まで（パネルが受け取る上限）．超えたら `tools/build.py` が書き出しを止める．絵が大きいキャラクターほど，その絵のまま並べられる演者は少ない（「表示」が述べる）

### 絵の名前

絵の名前は，誰が（本体か分身か）・どの役割を・どの眠気で演じるかを表す．役割と眠気は「役割」「本体の眠気」が定める．

| 名前 | 絵 |
| --- | --- |
| `main-<役割>-<段階>` | 本体の，眠気の段階ごとの絵（段階は0〜3） |
| `main-<役割>` | 本体の，眠気を描き分けない絵 |
| `sub-<役割>` | 分身の絵．分身に眠気は無い |

役割は `think`（考える）・`research`（調べる）・`write`（書く）・`run`（実行する）・`watch`（見守る）・`call`（呼ぶ）・`rest`（眠る）である．「眠る」を除く6つを，働く役割と呼ぶ．

要るのは本体の「考える」（`main-think-0` か `main-think`）だけである．持っていない絵は，次の順で探して代える（`hooks/cast.ts` の `spritesOf`）．

1. 分身の絵が無ければ，本体の絵（分身に眠気は無いので，段階0として探す）．
2. その眠気の段階の絵が無ければ，段階0の絵，それも無ければ描き分けない絵．
3. その役割の絵が無ければ，「考える」の絵（同じ順で探す）．

だから，キャラクターは1枚の絵から始められ，絵を足すほど，描き分けられる姿が増える．

### 一覧

`sprites/index.json` は次を持つ．

| 項目 | 中身 |
| --- | --- |
| `ticks` | 1周の刻みの数 |
| `sprites` | 持っている絵の名前 |
| `variants` | 個体ごとに置き換える色の組．先頭の組が，絵に描かれた元の色である．無ければ空 |

### 個体ごとの差

同じ役割でも，分身ごとに動きと色を少しずつ変える．分身の id から乱数の種を作り，読み込んだ SVG の文字列を置き換えて付ける．

- 動きの位相：アニメーションの開始位置を，1周のどこかの刻みへずらす（並んだ分身が同時に動かないようにする）
- 色：`variants` の組のどれかを選び，元の色をその組の色に置き換える．置き換えは全ての絵に効くので，置き換える色を，変えたくない部分に使わない

### 書き出し

リポジトリの最上位で，`python plugins/theater/tools/build.py <キャラクターのディレクトリ> [確かめ用.gif]` を走らせる（Pillow が要る）．絵の元は，キャラクターの `art/` から読む．

- `art/draw.py` があれば，それを読み込む．`sprites()` が，絵の名前ごとに刻みごとの絵（64×64ドットの RGBA）を返す．`VARIANTS`（個体ごとに置き換える色の組）と `ICON`（アイコンにする絵）は，あれば使う
- 無ければ，`art/` の GIF を読む．ファイル名（拡張子を除く）が絵の名前になる．GIF は，コマの長さを100msの倍数に，大きさを64ドットの整数倍の正方形に作る（外れると `tools/build.py` が弾く）

書き出すのは，`sprites/`，アイコン（`.claude-plugin/icon.png`．512ドット．`ICON` が無ければ，本体の「考える」の刻み0），README のプレビュー（`preview.gif`．本体の働く役割を，透過の背景に1段で並べる．1体128ドット）である．パスを渡せば，全ての絵を黒背景に6つずつ並べた確かめ用のプレビューも作る．並ぶ順は，本体の働く役割（段階0．無ければ眠気を描き分けない絵），分身の働く役割，本体の眠気の段階1・2・3それぞれの働く役割，「眠る」である．確かめ用のプレビューは，リポジトリには入れない．どちらのプレビューも，色を減らさず，絵に説明の文字を入れない．

## 役割

- 役割は「いま何をしているか」で分け，ツール名から決める．エージェントの種類は使わない．分身の多くは汎用の種類で，種類で分けるとほとんど同じ姿になるため
- 役割は作業の種類（状態）だけにする．終了などの一瞬の出来事は役割にしない
- 表示は「最後に使ったツール」の役割を，次のツールまで続ける．読む・直すなどのツールは一瞬で終わり，待ち時間の大半はツールの合間（Claude が考えている時間）なので，ツールの実行中だけ役割を出すと，ほぼ「考える」になってしまう
- 役割は，一度出したら最低2秒続けてから切り替える（`hooks/cast.ts` の `HOLD_MS`．2秒は仮の値で，「残り」の1で決める）．種類の違うツールが同時に呼ばれたときの，ちらつきを防ぐため
- 「呼ぶ」は，この2秒を待たずに，すぐ出す．ユーザーの返事か許可を待っていたツールが終わったら，最後に使ったツールの役割へ戻す
- どの役割にも当たらないツール（MCP のツールなど）は「考える」にする

役割は，働く6つと，働き終えた「眠る」の7つである．ツール名と役割の対応は `hooks/cast.ts` の `ROLE_OF` が持つ．役割をどんな姿で演じるかは，キャラクターが決める．

| 役割 | きっかけ |
| --- | --- |
| 考える | 最初のツールの前，計画のツール，その他のツール |
| 調べる | Read・Grep・Glob・WebSearch・WebFetch（手元のファイルもウェブも区別しない） |
| 書く | Write・Edit・NotebookEdit |
| 実行する | Bash・PowerShell |
| 見守る | 分身を起動するツール（Agent．旧名の Task も）．前で動く（起動した側が終わりを待つ）分身なら，終わるまで続く．裏で動く（待たない）分身なら，起動した演者は自分の作業を続けるので，次のツールで別の役割に替わる．本体は，自分の作業を終えて分身を待つ間，ふたたび「見守る」になる |
| 呼ぶ | 質問（AskUserQuestion．本体だけ），許可待ち（分身の許可待ちなら，その分身が呼ぶ） |
| 眠る | 本体：返答を終え，働いている分身もいないとき．裏で分身が動いていれば「見守る」になる．分身：仕事を終えてから，パネルの列を外れるまで |

分身の働く役割は，本体と同じ6つである．分身も自分の分身を起動できるので，「見守る」も演じる．分身は質問を使えないので，分身の「呼ぶ」は許可待ちのときだけである．

## 本体の眠気

本体のコンテキストの量は，眠気の段階（0〜3）で表す．境目は `hooks/cast.ts` の `DROWSY` が持つ．窓（コンテキストに入る量の上限）に対する割合でなく，トークン数で決める．Claude の精度は量につれて落ち，100万トークンの窓で割合を取ると，眠くなるのが遅すぎるからである．段階2の始まり（15万）は，baton（長い会話の引き継ぎを担うプラグイン）が，新しいセッションへ移ることを勧める量に合わせる．ほかの境目は仮の値で，「残り」の1で決める．20万トークンの窓では，20万に届く前に自動の圧縮（古いやり取りを要約に置き換えること）が走るので，段階3は出ない．

| 段階 | トークン数 |
| --- | --- |
| 0 | 10万未満 |
| 1 | 10万以上，15万未満 |
| 2 | 15万以上，20万未満 |
| 3 | 20万以上 |

会話の圧縮でトークン数が減ったら，減ったあとの段階へ戻る．分身には眠気を付けない．

## 眠りの深さ

本体が眠る間（返答を終え，働いている分身もいないとき），パネルの下に，プロンプトのキャッシュが切れるまでの残りを1行で書く：「深く眠るまで，あと<N>分．」．切れたら「深く眠っている．」に替え，行は消さない（切れたことに気づけるように）．話しかけて本体が起きれば，行は出ない．端末のパネルでも，役割の一覧の下に同じ1行を書く．眠りの深さは，眠気の段階（会話の量）とは別の軸である．

- キャッシュが切れても，Claude は何も忘れない．次の依頼で，会話をキャッシュから読めずに初めから読み直すので，費用と待ちが増えるだけである．そこで「忘れる」とは言わず，眠りの深さで言う
- 寿命は，本体がモデルへ送る要求（`turn.step`）ごとに，その使用量から決める（`hooks/cast.ts` の `cached`）．キャッシュに書いた要求は，その書き込みの寿命（5分か1時間．両方なら短い方）を持つ．読むだけの要求は，前と同じ長さの寿命を，その要求を送った時刻から改めて持つ（読めばキャッシュは延びる）．読みも書きもしない要求と，使用量が届かない要求は，前の寿命をそのまま残す．起点は，応答を受け取った時刻でなく，要求を送った時刻である
- 残りは分単位で切り上げて書き，残りの分が変わる時刻に描き直す．「あと1分」の次が「深く眠っている．」である
- 寿命がまだ分からない（このセッションで，本体の要求がキャッシュに書いていない）ときは，行を出さない．圧縮と会話の消去のあとも，本体の要求が次にキャッシュに書くまでは出さない．会話が置き換わり，前の寿命は次の要求に当たらないためである
- この行と，省いた演者の断り（「表示」が述べる）が両方出るときは，断りを先に書く．断りは絵の列の説明なので，列の側に置く

## 並べ方

本体と分身の数だけ演者を並べる．本体は常に先頭に置く．分身は加わった順に並べるが，「呼ぶ」の分身は本体の次へ寄せる（`hooks/cast.ts` の `lined`）．演者の列はパネルの幅で折り返すので，「呼ぶ」の分身が下の段に隠れると，待たせていることを見落とすためである．

- 絵は，何体並んでも同じ大きさで描く．分身が現れたり消えたりするたびに本体の大きさが変わると，落ち着かないためである．小さく描くと，絵の下に書く一言（その演者が受けている指示）が収まらない．大量の分身を起動することは少ないので，大きめに描く
  - パネルが横に置かれているときは4倍（256ドット）にする
  - パネルが入力欄の上に置かれているときは3倍（192ドット）にする．このパネルは背が低く，256ドットでは1体でもスクロールバーが出る．パネルには1体ぶんの絵と一言が収まる高さを頼む（`hooks/register.tsx` の `ROWS`）が，VS Code では，頼んでも256ドットが収まる高さにならない
- 1段に並ぶ数は決めず，パネルの幅に入るだけ横に並べて折り返し，各段を中央に寄せる．折り返して段が増えたときは，スクロールして見る
- 仕事を終えた分身は，すぐには外さない．すぐ消えると，短い仕事の分身は見る間もないためである．眠る姿で列に残し，ユーザーが次の依頼を送ったときに外す．完了の知らせや分身からの報告など，機械が入れた番（会話に入る1件の入力）では外さない（依頼の出どころで見分ける）
- 絵の下に，その演者がいま受けている指示を一言で書く（「ログの調査」のように，何を受け持つかが分かる名詞句）．決まった文句は書かない．絵の幅に収まらない分は切る
  - 一言は，その演者に指示が届いたときにだけ付け替える．1体の演者は1つの指示の間に調べたり実行したりと色々なことをするが，その間，受けた指示は変わらないためである．何を頼まれているかを一言が，いま進めている作業を絵（役割）が表す
  - 分身：起動のときに付けられた仕事の名前（数語）をそのまま使う．名前が分からなければエージェントの種類を書く．追加の指示が届いたら，指示に付いた要約に付け替える（要約が無ければ替えない）
  - 本体：ユーザーの依頼が届くたびに，その文から小さなモデル（`hooks/register.tsx` の `LABELER`）に付けさせる．依頼1件につき短い呼び出しが1回走り，その費用はセッションに計上される．依頼の受け付けは待たせず，新しい一言が届くまでは前の一言を出しておく．モデルが答えないか，一言を付けずに依頼そのものに答えたときは，依頼の文をそのまま書く．スラッシュコマンドの入力からは付けない（指示の文ではないため）
    - 返事の1行目が，半角24字の幅（`hooks/register.tsx` の `LABEL_WIDTH`）を超えるか，句点・疑問符・感嘆符で終わるなら，依頼そのものに答えたとみなす
    - 依頼の文には，画面が足した段が混ざる．VS Code は，ブラウザ操作の案内や，開いているファイルの知らせを，名前に `_` か `-` を含むタグで囲んで，依頼の前に足す．ユーザーが書いた文ではないので，モデルに読ませる前に除く（`hooks/register.tsx` の `INJECTED`）．貼り付けた文を囲むタグは，タグだけを外す．ユーザーが書いた部分が残らなければ，一言は付け替えない

## 仕組み

### キャラクターとのつなぎ方

導入されたプラグインは1つずつ別の場所に展開されるので，キャラクターは theater のファイルを読み込めない．そこで theater は，`$` に名詞 `theater`（`$.theater` で呼べる操作の束）を足す（`engine.create`）．キャラクターは theater を `dependencies` に宣言して `$.theater.join` を呼ぶ．名詞の型は `types/index.d.ts` が持ち，Claude Code が依存する側へ配る．

名詞を足す場面では `$` を使えないので，名詞には，要る操作（パネルを開く・コマンドを登録する・描き直す）だけを渡す．加わったキャラクターは，モジュールの変数に持つ．モジュールが読み込み直されると変数は空になるが，そのときはセッションの開始の出来事ももう一度起き，キャラクターが加わり直す．

キャラクターが加わる時機と，theater 自身がセッションの開始を拾う時機は，どちらが先とも決まっていない．どちらが先でも，パネルを自動で開く画面では，映すキャラクターが決まるか替わるたびに，パネルをその題で開く．

### 表示

閉じるまで出たままのパネルを開く．VS Code・デスクトップアプリ・モバイルのパネルに置ける絵はベクター画像（SVG）だけで，GIF は置けない．そこで絵ごとに，1周ぶんの刻みを1枚のアニメーション SVG に焼いておき，パネルはそれを1体につき1枚置く．絵を動かすのは SVG の中の CSS アニメーションである．プログラムが描き直すのは，次の3つのときだけである：状態（役割・一言・並び・眠気など）か映すキャラクターが変わったとき，眠りの深さの残りの分が変わるとき，VS Code で動かす絵を入れ替える2回目の描画のとき（`hooks/register.tsx` の `movable`）．

- `tools/build.py` は，見せる刻みが同じドットを1つの層にまとめ，層ごとに見せる・隠すを切り替える．SVG を短くするために，1周の間ずっと不透明な位置では，最も長く見せる色を下地として常に見せ，ほかの色をその上に重ねる．ある層の見せる刻みを，ほかの層を幾つか合わせてちょうど覆えることがある．そのときは，その層のドットを，合わせた層のそれぞれへ配れば，その層を無くせる．配った先で増える文字数が，無くして減る文字数より少ないなら，そうする．下地の層は配らない
- VS Code は，パネル1枚の文字を，絵の SVG も合わせて262,144字までしか描かない．上限に達した演者から後ろは，画面に出ない．そこで VS Code では，並べる絵の大きさの合計を25万字（`hooks/register.tsx` の `ROOM`）に収める．絵を先に取る順（本体，「呼ぶ」の分身，ほかの働く分身，眠る分身．`hooks/cast.ts` の `ranked`）に，残りに入る絵を出す．入らない絵を，小さい絵では代えない．絵と一言は組で出すので，絵が入らない演者は一言ごと省き，パネルの下に，省いた演者の数を断る
- VS Code が同時に動かす絵は，1つのプラグインにつき6枚までで，先に動き始めた絵が枠を持ち続ける．そこで VS Code では，動かす絵を，絵を先に取る順の6体までにし（省いた演者は数えない．`hooks/register.tsx` の `MOVING`），残りは刻み0の姿で止めて描く．眠る分身が枠を持ったまま，働く分身が止まるのを防ぐためである
- 枠は，絵が並び順に1枚ずつ VS Code に頼んで取る．枠が空いていないときに頼んだ絵を，VS Code は止めて描く．その絵が枠を頼み直すのは，1分ほど後である．そこで，動かす絵の入れ替えは2回の描画に分ける：外す絵を先に止め，0.5秒後の描画で，入る絵を動かす（`hooks/register.tsx` の `movable`）
- 絵の大きさと動かす数の上限，入れ替えの分け方は，VS Code の決まりに合わせたものなので（拡張機能 2.1.332 のコードで確かめた），VS Code の画面でだけ当てる．デスクトップアプリとモバイルでは，全ての演者を，その絵のまま動かす．画面の種類は，パネルの描画が受け取る `surface`（VS Code は `vscode`）で見分ける
- 動きを減らす設定の人には，デスクトップアプリがアニメーションを外して描く．そのときは刻み0の絵で止まる（`tools/build.py` の `FROZEN`）．刻み0に見せない層だけを，素の状態で隠してある
- 端末はベクター画像を描けないので，絵は出さず，役割と一言を文字で並べる．端末ではパネルが画面の一部を取るので，自動では開かず，キャラクターのコマンドで開く
- VS Code・デスクトップアプリ・モバイルでは，セッションの開始時と，画面がセッションにつながったときに自動で開く．閉じたパネルは，キャラクターのコマンドで開き直す
- パネルは，開いても置かれないことがある．たとえば，描く画面がセッションにつながっていなければ，置かれないまま，つながるのを待つ．置かれなかったとき，キャラクターのコマンドはその理由を伝える

### 拾う出来事

出来事のフックは眺めるだけで，結果には手を付けない．答えを返すのは，名詞を足すフックと，キャラクターのコマンドと，パネルの描画だけである．

| 出来事 | すること |
| --- | --- |
| エンジン（Claude Code の，会話とツールを動かす部分）の組み立て（`engine.create`） | `$` に名詞 `theater` を足す |
| セッションの開始（`session.start`） | ユーザーが最後に選んだキャラクターの名前を読む．端末でなければ，パネルを開く |
| 画面の接続（`session.attach`） | 端末でなければ，パネルを開く |
| コマンドの実行（`command.run`） | キャラクターのコマンドなら，そのキャラクターを映すキャラクターにし，名前を残して，パネルを開く．ほかのコマンドには手を付けない |
| ツールの許可の判定（`tool.check`） | ツールを呼んだ演者の役割を，ツール名から決める．質問のツールなら「呼ぶ」にする．分身の中の呼び出しにはその分身の id が付き，本体の呼び出しには付かない．分身へ追加の指示を送るツールなら，宛先の分身の一言を付け替える |
| 許可待ち（`classic.PermissionRequest`） | 「呼ぶ」にする |
| ツールの終了・失敗・不許可（`classic.PostToolUse`・`classic.PostToolUseFailure`・`classic.PermissionDenied`） | 返事か許可を待っていたその呼び出しの「呼ぶ」を解く．許可待ちの出来事は呼び出しの id を持たないので，許可待ちは同じ名前のツールの1件ぶんを解く |
| 分身の開始（`classic.SubagentStart`） | 列に加え，仕事の名前をエージェントの一覧から読む |
| 分身の終了（`classic.SubagentStop`） | 眠らせて，列に残す |
| 依頼の提出（`prompt.submit`） | ユーザー自身が送った依頼なら，終えた分身を列から外し，本体の一言を付け替える．映すキャラクターがいなければ，一言は付けない |
| 依頼の受け取り（`classic.UserPromptSubmit`） | 本体を「考える」に戻す |
| モデルへの要求（`turn.step`） | 本体の要求なら，送った時刻と応答の使用量から，キャッシュの寿命を決める．応答はそのまま通す．分身の要求には手を付けない |
| 返答の終了（`classic.Stop`） | 本体を止める（働いている分身がいれば「見守る」，いなければ「眠る」）．終了の出来事を取りこぼした分身と，10分動いていない分身を，終えた扱いにする |
| 圧縮の終了（`classic.PostCompact`） | 眠気を測り直す．キャッシュの寿命を忘れる |
| 会話の消去（`/clear`．`classic.SessionStart`） | 列を，本体1体だけの最初の状態に戻し，キャッシュの寿命を忘れる |

眠気は，本体がツールを使うとき・依頼を受け取ったとき・返答を終えたとき・圧縮を終えたときに，コンテキストのトークン数から測り直す．

- ツールの呼び出しを `tool.call` で拾わないのは，そこにフックを掛けると，エンジンがそのツールを裏へ回せなくなるためである
- 分身は，開始の出来事で列に加える．プラグインが会話の途中で読み込まれたために，開始の出来事を取りこぼした分身は，ツールの呼び出しを拾ったときに，エージェントの一覧に載っていれば加える．エンジン自身の内部の処理（圧縮など）も id を持つが，開始の出来事が無く，エージェントの一覧にも載らないので，列には加わらない

### 確かめ方

次の2つを，リポジトリの最上位で走らせる．

- `claude plugin validate plugins/theater`：プラグインの読み込みと型を確かめる
- `claude plugin test plugins/theater`：状態の決まりとパネルの描画を，`hooks/theater.test.tsx` で検査する．検査の中のキャラクターは，検査が自分で立てる

絵を変えない `tools/build.py` の直しでは，書き出す絵が変わらないことを，次の順で確かめる．

1. 直す前に，手元のキャラクターのディレクトリと確かめ用のパスを渡して `tools/build.py` を走らせ，書き出し（`sprites/`・アイコン・2つのプレビュー）を別の場所に写す．
2. 直したあとに，もう一度走らせる．
3. 直した関数が書かないファイルは，1で写したものと1バイトも違わないことを確かめる．
4. 直した関数が書くファイルは，バイトが変わってよい．読み戻して，絵の元と1ドットずつ突き合わせる．

4で突き合わせるのは，プレビューなら全ての刻み，SVG なら全ての刻みとアニメーションを外した絵である．アイコンとプレビューは Pillow で読み戻せる．SVG を読み戻す道具は置いていないので，層とキーフレームから各刻みの絵を組み立てる．

### 既知の限界

- ツールに許可を出したあとも，そのツールが終わるまで「呼ぶ」が続く．許可が出た瞬間に起きる出来事を，ツールの実行を妨げずに拾う方法が無い
- 許可を待つツールと同じ名前のツールが先に終わると，まだ許可を待っていても「呼ぶ」が解ける．許可待ちの出来事が呼び出しの id を持たず，どの呼び出しが待っているかを見分けられない
- VS Code は，絵を，パネルとは別の描画用の領域で1コマずつ描き，遅い絵を自分で止める．1コマに100msより長くかかると，絵を長くて5分のあいだ止めて描く．絵の読み込みに2秒より長くかかるか，描画用の領域が立ち上がらないと，絵を長くて5分のあいだ出さず，代わりに読み上げ用の文（「本体：考える」など）を書く．PC の処理が重いときに起こり，時間が経てば元に戻る．theater の側では防げない
- 眠りの深さの行は，キャッシュが実際より早く切れたように出ることがある．本体の要求の外で同じ会話を読む要求（ほかのプラグインの `$.model.fork` など）もキャッシュの寿命を延ばすが，theater は寿命を本体の要求（`turn.step`）からだけ決める
- 使用量がキャッシュの寿命を伝えない接続先では，眠りの深さの行が出ない
- 役割が替わるたびに，アニメーションは最初から始まる（実機のパネルでは，ちらつきには見えない）
- 端末では絵を出さない
- クラウドセッション（Anthropic のクラウドで動かすセッション）のパネルは，デスクトップアプリでは出るが，モバイルでは出ない（iOS アプリで確かめた）．theater の側では直せない

## 残り

1. 眠気の境目（段階2の始まりを除く）と，役割を続ける長さを，実機で動かして決める．
2. 分身を，本体と別のキャラクターの絵で映すかを決める．いまは，演者はみな同じキャラクターの絵で映る．
