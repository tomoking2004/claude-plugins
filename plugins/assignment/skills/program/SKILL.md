対象：課題のうちコードで応える部分（実装・スクリプト・ノートブック等）．

## 手順

1. **受領**：[RUBRIC.md](../../RUBRIC.md) を読み，その**進行**（受領・納品・修正）に従う——本スキルは実装の段を担う．ブロッキング項目が残る間は着手しない．
2. **実装**：出題文・採点基準を目的として，下の「領域の正典」に従って書く．
3. **仕上げ**：/refine:code を発動し，美の6条で確定版へ仕上げる——美の基準（BEAUTY.md）は refine プラグインの正典であり，本スキルはそれを二重定義しない．委譲の際は，必要十分の基準となる目的が出題文・採点基準であることと，仕上げる対象が外へ出す成果物であることを明示する（成果物の文脈から推測させない）．検査役は委譲元が立てるので，委譲先には立てさせない．/refine:code が見えなければ，refine プラグインの導入を促して中断する．
4. **走査**：下の「固有の走査」と RUBRIC.md の**遵守ゲート**・**走査の規律**を全件通し，欠陥ゼロを確認して確定する．納品するかは同書の**進行**に従う——単独で呼ばれたなら本スキルが納品し，委譲されたなら束ねて出すのは委譲元の責務なので納品しない．

## 領域の正典

言語は出題文の指定に従い，無ければ既存ファイル・分野の慣習に合わせる．ライブラリ・言語機能・実行環境（バージョン等）は，使用可否の指定があれば従う．スタイルの正典は持たない——美の仕上げは手順3で /refine:code に委ねる．

## 固有の走査

- **要求対応表**：自分に割り当てられた要求項目（単独で呼ばれたなら出題文・採点基準の全項目——入出力形式・関数シグネチャ・与えられたテストケース等）と実装箇所を一対一で対応させ，満たさないものを潰す．
- **実行確認**：与えられたテストケース・境界値・異常系を実際に実行し，結果を裏取りする（数十秒で終わるものは /ops:exec を挟まない）．

## 制約

動作をテスト・実行で確かめる．仕様の解釈が割れる箇所は推測せず問う．問い方：調べて届くことは調べ尽くし，ユーザーにしか分からないことだけを最初にまとめて問う．問いには調べた範囲・対象の原文・問う理由・答えで変わることを書き，未確認の前提で選ばせない．対象が一通りに読めるなら問わずにその読みで進め，採った読みを報告に1行載せる．ユーザーの発話が問いの形なら，依頼と読まず問いとして答える．

## 失敗時

/heal:skill を呼ぶ．
