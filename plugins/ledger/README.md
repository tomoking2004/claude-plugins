# ledger

プロジェクトの中身について決めたことと確かめた事実を，承認された分だけ .ledger/ に記録し，会話の始まりに要る分だけを Claude に渡す．

## CLAUDE.md との分担

CLAUDE.md（`.claude/rules/` と `CLAUDE.local.md` を含む）は作業の仕方を，`.ledger/` はプロジェクトの中身を持つ．

- **CLAUDE.md**：どう作業するか．コマンド，書き方の約束，道具と環境，作業フォルダの扱い，してはいけない操作．人が書いて整え，めったに変わらない．
- **`.ledger/`**：何を作り，何が分かったか．目的，仕様，設計の決定，仮説，評価の基準，外の制約，調べて分かったこと，未決の問い．会話の中で Claude が案を書き，人が認める．仕事が進むにつれて決まり，改まり，取り消される．

研究のリポジトリなら，作業フォルダの扱いは CLAUDE.md に，研究の目的・仮説・評価の基準は `.ledger/` に置く．

## 導入

手順はマーケットプレイスの README（リポジトリ最上位の README.md）が定める．

- **対応先**：Claude Code 専用．記録は会話をまたいで残るプロジェクトのファイルにあり，それを渡すのも Claude Code の拡張の仕組み（mod）なので，Claude には追加できないようにしてある．
- **依存先**：heal

## 使い方

- **記録する**：「この方針を記録して」と頼むと，/ledger:update-ledger が書き込みの案を示す．プロジェクトにまだ `.ledger/` が無ければ，それを作る場所も案に入る．書かれるのは，番号か「全部」で認めた案だけである．「この決定は取り消して」「こう改めて」と頼めば，消す案と改める案を示す．作業の仕方に当たる事柄は記録せず，CLAUDE.md に置く案として示す．
- **続けて使う**：`.ledger/` のあるプロジェクトでは，会話の始まりとコンテキストの圧縮のあとに，ledger が記録を Claude に渡す．渡るのは，どの仕事にも効く項（`general.md`）の全文と，特定の仕事にだけ効く項（`<主題>.md`）の題の一覧である．Claude は，その仕事に触れるときに主題のファイルを開く．記録に値することがあれば，返答の末尾に案を添える．答えなかった案と断った案は書かれず，同じ会話では再び示されない．
- **整理する**：渡す量が4,000字を超えると，ledger は `general.md` も題だけにして，整理を勧める．/ledger:tidy-ledger は，事実を実物と突き合わせ，重複・食い違い・済んだ項を探し，ファイルを分けるか畳むかを案にする．
- **CLAUDE.md から移す**：/ledger:tidy-ledger は，CLAUDE.md にあるプロジェクトの中身と，`.ledger/` にある作業の仕方を探し，境目の正しい側へ移す案を示す．認めた案に限って，両側を一度に書き換える．既に CLAUDE.md に中身を書いてきたプロジェクトでは，`.ledger/` を作ったあとに一度使う．
- **git で共有する**：`.ledger/` は，コードと一緒に追跡する前提で置かれる．記録はいまの姿だけを持ち，前の文面は git の履歴が持つ．記録を git に載せたくなければ，プロジェクトの `.gitignore` に `.ledger/` を足す．コミットは利用者がする．
- **私用を分ける**：後の仕事を縛る個人の事情と，利用者が私用と言った事柄は `.ledger/local/` に入る．事情から決まった決定は，事情を除いた文面で追跡される側に置かれる．`local/` は `.ledger/.gitignore` が git から外すが，フォルダを同期する道具（クラウドの同期など）には載る．パスワード・鍵・トークンは，値でなく在処だけが記録される．
- **git の外で使う**：記録は，作業ディレクトリの `.ledger/` からだけ読まれる．上の階にある別のプロジェクトの記録を，取り違えて使わないためである．会話は，`.ledger/` のあるフォルダで始める．

記録の形と書き込みの決まりは [LEDGER.md](LEDGER.md) が定める．ledger は，`~/.claude/` の下と自動メモリを書き換えない．利用者自身の好みと，プロジェクトをまたぐことは，そちらに任せる．
