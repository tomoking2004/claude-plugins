# baton

会話が長くなったら，返答の区切りで新しいセッションへ移ることを勧め，そのまま貼れる引き継ぎ文を渡す．

## 導入

手順はマーケットプレイスの README（リポジトリ最上位の README.md）が定める．

- **対応先**：Claude Code 専用．入力欄の上の帯は Claude Code の画面拡張（mod）で，チャットでは働かないので，Claude には追加できないようにしてある．
- **依存先**：なし

## 使い方

- **勧め**：入力欄の上の帯が，新しいセッションへ移ることを勧める．帯は，コンテキストが15万トークンに達した返答の区切りと，会話が自動で要約されたあとの区切りに，1回ずつ出る．帯は，閉じるか，`/baton` か `/clear` を走らせるまで残る．勧めはユーザーにだけ出し，Claude には伝えない．
- **見立て**：帯は残りの仕事を見ずに出るので，移るのが得とは限らない．`/baton` を走らせると，いまの会話を受け継いだモデルの呼び出し（分岐）が，まず移るのが得かを見立てる．残りの仕事がわずかで，このセッションで済ませるほうが安いなら，続けることを勧める．仕事が片づいていて運ぶものが無いなら，何も渡さずに新しいセッションを始めることを勧める．どちらのときも引き継ぎ文は書かない．それでも書かせるなら，すぐにもう一度 `/baton` を走らせる（間に別の文を送ると，次の `/baton` はまた見立てる）．
- **引き継ぎ文**：移るのが得なら，分岐が引き継ぎ文を書く．型は無く，長さは会話が決める——続きに要ることがプロジェクトのファイルにもう書いてあれば，そのパスを示す1行で済ませ，ファイルに無いこと（目的・決めたこと・済んだこと・確かめていないこと・次の一手）だけを書き足す．ユーザーの最後の依頼と制約は，短く済むときも原文で引く．確かめていないことが無ければ，無いと書く．baton は引き継ぎ文をクリップボードに写す．同じプロジェクトで新しいセッションを始めると（`/clear` でもよい），引き継ぎ文が入力欄に下書きとして入る（打ちかけの下書きは上書きしない）．
- **モデルとエフォート**：引き継ぎ文と併せて，次のセッションに合うモデルとエフォートを，残りの仕事の性質（判断や設計が重いか，手順の決まった作業か）から理由付きで勧める．エフォートは，変える理由が無ければ「既定のまま」と勧める．モデルとエフォートの勧めは `/baton` の出力に出るだけで，切り替えるのはユーザーである（`/model` と `/effort`）．`/model` で替えたモデルは以後のセッションの既定にもなるので，出力はそのことも断る．
- **費用**：分岐は Claude をもう1回呼び出すので，その分の費用がかかる．
