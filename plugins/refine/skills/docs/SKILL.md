対象：指定された範囲の文書；無指定ならプロジェクト全文書（生成物のみ除く；`.gitignore` 対象も走査し，私的なメモ等は変えてよいかを先に問う）．

まず [BEAUTY.md](../../BEAUTY.md) を読み，美の6条と走査の規律に従う．

## 媒体の正典

- **Markdown**：表題は一つ（H1 か frontmatter）；見出し階層は飛ばさない；列挙は文型・粒度を揃える；表は二つ以上の対応を並べるときだけ置く（1行の表・同じ語が並ぶ列を置かない）．手順は実行に要る入力・在処まで書く．
- **README**：何であるか→なぜ→導入→使い方→開発の順．
- **SKILL.md**：description に機能と発動条件を最小トークンで（全セッションに常駐する）；本文に一般知識と由来は書かない——由来はコミット本文へ．規則には一つの事例に固有の条件を混ぜない．
  - **description**：短くしても文として成立させ，字数と衝突したら成立を採る．発動語には一つの事例に固有の言い回しを混ぜない．スキルが答える問いの言葉で書く．近いスキルの description と並べ，どの依頼でどちらが発動するかを模擬する．
  - **読む量**：毎回要る部分と場面でだけ要る部分を分け，後者はその場面の手順から指す——毎回開く量が実測で減るときだけ分ける．
  - **網は必ず持つ**：確定前に当てる検査であり，当たる先で名が決まる——成果物に当てるなら**固有の走査**，成果物を残さず自分の段取りに当てるなら**自己点検**．網が手順と一体なら手順の中で走査を明示し，別節に写さない（単一の真実）．
  - **節の順序**：「対象：」の一行 → 動的コンテキスト（読み込み時に走るコマンドの出力；あれば）→ 手順 → 判断規則（媒体の正典・文面の基準等）→ 網 → 制約 → 失敗時（/heal:skill を呼ぶ）．手順を持たない走査スキルは判断規則から始める；制約は手順に収まらない禁止・例外があるときだけ置く．
  - **倣えと命じるなら手本を見せる**：「既存の声・様式に倣う」類の規則は，倣う対象を動的コンテキストで**実物のまま**出し（件名・要約・統計では声は伝わらない），網に「手本と**並べて**確かめる」項を置く．見せずに倣えとだけ書けば，読み手は想像で補う——規則を持ちながら守れない状態になる．この規則が及ぶのは**手本が固定のコマンドで取り出せるとき**に限る（`git log`・`gh release view` 等）．「既存ファイルの多数派に倣う」のように倣う対象が実行時の範囲で初めて決まるものは動的コンテキストに置けないので，代わりに**どこを見れば手本があるか**を規則自身が名指しする．
  - **倣う対象が選択なら条件と対で見せる**：倣わせたいものが**条件に応じた選び方**（変更の種類に対するコミットの type，リリースノートに載せる項目の取捨等）なら，選んだ**結果**だけを並べても倣えない．読み手は結果の語彙に自分の選択が入っていることを確かめ，「一致した」と判定して網を通してしまう（開発ツールに `chore` を当てるリポジトリで，語彙に `feat` があるからとツールの機能追加を新機能扱いする類）．**条件と結果の対**を出すこと——`git log --format='%h %s' --name-only` のように「何を変えた回がどれを選んだか」が見える形にする．対を固定のコマンドで出せないなら，倣えとは命じず**規則そのものを書き下ろす**．
  - **道具の仕様は写さない**：ツールの引数は呼び方を定めるのに要るものだけを書いて実物のスキーマと照合し，既定値・上限は書かない——ハーネスが実行時に見せる値の写しは，黙って失効する．
  - **動的コンテキスト**：起こりうる全状態（非 git・初コミット前・タグ無し・**タグが HEAD**・作業ツリーが清潔等）で実行して裏取りし，**exit 0 かつ非空の出力**を保証する．非ゼロ終了はスキルの呼び出しごと止める（検索・比較の exit 1 だけは止めない）．出力が空でも exit 0 は起こるため `<cmd> || echo "（なし）"` では足りない——`git log "$tag..HEAD"` はタグが HEAD にあるとき成功しつつ何も返さず，代替文が発火しない．出力が空の節は何を示すのか読み手に分からないので，`x=$(git log "$tag..HEAD"); [ -n "$x" ] && echo "$x" || echo "（なし）"` の形で必ず何かを出す．
- **日本語の散文**：README・SKILL.md の本文・レポート等に当てる．
  - **指示語**：「それ・これ・その・この・同じ・両者」の受け先を，同じ単位の中で一つだけ指せる．
  - **主述と目的語**：主語と述語を抜き出して対応させる．目的語を要求する動詞・動作の名詞に目的語があり，省いた主語が一つに決まる．
  - **修飾の掛かり**：連体修飾が，意図しない直後の名詞に掛かると読める箇所が0件．
  - **文のつながり**：隣り合う二文の関係を「だから・しかし・そこで・たとえば・つまり」のどれかで言い直せる．
  - **一文一義**：因果でも時間でもつながらない二つの事柄を一文に入れない．100字を超えた文は分けられないか確かめる——長さそのものは違反でない．
  - **近接の反復**：一つの段落・項の中で同じ文末の3連続が0件．同じ語の近接も避ける（通すと決めた専門語は数えない）．
  - **定義が先**：専門語・固有名・略語は説明を先に置くか初出の句で言い添え，以後は同じ語で通す．
  - **比べる語**：「共通・同じ・違い・独自」は比べる相手を，「変わる」は何によってかを，同じ単位の中で示す．
  - **程度の語**：測っていない程度の語（大幅に・劇的に等）を使わない．
- **その他**：その媒体の公式スタイルガイド；無ければ既存ファイルの多数派．

## 固有の走査

- **参照整合**：リンク・相互参照・目次が実在の対象を指すことを全件確かめる．外部リンクは実際に開いて題名と中身を確かめる．失効した参照は付け替える前に依存そのものが要るかを問う．文書をまたぐ参照は番号でなく役割の名前で書く．外へ出す成果物は内部の構造に依存させず，読み手が到達できない参照先は内容を写す．
- **用語統一**：同義語群・表記の規約を全文書横断で列挙し，揺れを潰す．日付・番号・呼び名を変えたら，その値に触れる全箇所を同じ回に直す．
- **写しの印**：避けられない写しには写しであることを示すか，機械で同一を検査し，元（正）→写しの向きでだけ直す．
- **読み手**：誰が，何を手元に持ち，どれだけの時間で読むかを一文で言い，量がそれに収まるか確かめる．
- **自足**：各単位を単独で読み，初出で紹介されない指示対象・比較の相手・内輪の語が無いか確かめる．
- **自己記述**：文書が自分について述べたこと（数・位置・原則）が本文の実物と一致し，その原則を文書が守っているか確かめる．
- **到達可能性**：入口（目次・手順・description）から全節に辿り着け，禁止・例外・断り書きがそれの効く位置にあるか確かめる．
- **経緯の残留**：「しました」「確認済み」「予定」「TODO」と，他の文書の節番号への参照を検索し，作業の痕跡に当たるものが0件（規則の本文が語る語は数えない）．
- **入れ替え**：理由・動機・差別化を述べる文は，対象の名前を同種の別のものに入れ替えて読み，なお成り立つなら書き直す．
- **事実の文**：「書かれている」「とある」「明記」で検索し，原文を開いて句ごとに突き合わせる．引用符は原文の連続した文字列だけを括り，本文の表記規則で正規化しない．言い換えは向き・強さ・範囲・時制を出所に合わせる．
- **プレースホルダー**：入力する文字と見た目で区別できる記法を定め，その記法で検索して埋め忘れが0件．
- **意味保存**：短くする・畳む・移す回は，規則と確かめ方の数を前後で数え，旧版の一つひとつの在処か外した理由を示す．畳んだ後は，残した文に要る説明が揃っているかを，目的を定める文書と突き合わせて読み直す．

## 制約

git は読み込みのみ．スクリプトで一括編集するときは，編集箇所を一意な文字列で指定し，想定する一致件数をスクリプトに検査させ，結果を読み直して完了とする．判断の割れる箇所は推測せず問う．問い方：調べて届くことは調べ尽くし，ユーザーにしか分からないことだけを最初にまとめて問う．問いには調べた範囲・対象の原文・問う理由・答えで変わることを書き，未確認の前提で選ばせない．対象が一通りに読めるなら問わずにその読みで進め，採った読みを報告に1行載せる．ユーザーの発話が問いの形なら，依頼と読まず問いとして答える．
