# キツネが働くアニメーション

Claude（本体）とそのサブエージェント（分身）が処理している間，ドット絵のキツネが働く様子をパネルに映す．実用性は求めず，待ち時間を楽しく過ごすためのものである．

本書は絵と動きの決まり，絵を画面へ出す仕組み，確かめ方，残っている作業を定める．絵を直すときも仕組みを直すときも，本書を先に読み，直したら本書も合わせる．

## 構成

| 置き場 | 中身 |
| --- | --- |
| `.claude-plugin/plugin.json` | プラグインのマニフェスト |
| `.claude-plugin/icon.png` | プラグインの一覧に出るアイコン（目を開いた本体のベースキャラ．512ドット）．`art/build.py` が作るので，手で直さない |
| `bin/fox-claude-code-only` | プラグインを Claude Code 専用にする印 |
| `art/fox_main.gif`・`art/fox_sub.gif` | ベースキャラ（本体・分身） |
| `art/draw.py` | 役割ごとの絵を，ベースキャラに重ねて描く |
| `art/build.py` | 絵を `sprites/` へ，アイコンを `.claude-plugin/` へ書き出し，パスを渡せばプレビューも作る |
| `sprites/` | パネルが流すアニメーション（SVG．役割ごと，本体は眠気の段階ごとに1枚）と，個体ごとの表紙の色の一覧（`index.json`）．`art/build.py` が作るので，手で直さない |
| `hooks/hooks.json` | Claude Code に読み込ませるモジュール（`register.tsx`）を名指す |
| `types/index.d.ts` | キツネたちの状態の型 |
| `hooks/den.ts` | キツネたちの状態の決まり（役割の切り替え・眠気・列の片づけ） |
| `hooks/register.tsx` | Claude Code の出来事を拾い，パネルを描く |
| `hooks/fox.test.tsx` | `den.ts` と `register.tsx` の検査 |

絵を直したら，`art/` で `python build.py <プレビュー.gif>` を走らせる（Pillow が要る）．`sprites/` とアイコンが作り直され，全役割を黒背景に並べたプレビューが，渡したパスにできる．プレビューは目で確かめるためのもので，リポジトリには入れない．絵を変えない直しの確かめ方と，検査の走らせ方は，「確かめ方」が定める．

プレビューの1段目は本体の，2段目は分身の，働く6つの役割である（考える・調べる・書く・実行する・見守る・呼ぶの順）．3段目は，本体の眠気の段階0〜3（調べる役割で見せる）と，本体・分身の「眠る」である．役割と眠気は「役割とデザイン」が定める．絵には説明の文字を入れない．

Claude のチャットで絵を直すなら，`art/` の中身と本書を添付し，本書を読んで絵を直すよう頼む．あわせて，直したあとにプレビューを作り直して見せること，本書も直すこと，直したファイルをすべて返すことを頼む．返ってきたファイルを `art/` に置き，手元で `build.py` を走らせて `sprites/` を作り直す．

## ベースキャラ（確定）

- `fox_main.gif`（本体）・`fox_sub.gif`（分身）：64×64ドットを4倍に拡大（256×256），背景は透過，無限ループ，1周4.8秒（100msを1刻みとして48刻み．刻みは0から数える）．2つは同じ時刻に同じ姿勢で，違いは葉っぱだけ
- 見た目：耳先と足先が黒，尻尾の先が白，頬が赤く，口はω．分身はおでこに葉っぱを乗せる
- 待機アニメーション：目を開け閉めし（視線も左右に動く），体が1ドット沈み，尻尾が揺れ，左右の耳が別々の時刻にぴくっと動く．分身は，頭が揺れると葉っぱが少し遅れてついてくる
- 前足：ベースキャラには描かない（前足のないほうが美しいため）．前足を使う役割では，役割の絵が描く
- 目：開いた目は5×6ドットの焦げ茶（下側を明るく，左上に光）．大きな黒い目は不気味に見えるため，目を小さくし，柔らかい色にしている
- 縁取り：内側の線（耳の付け根・あご・体と後ろ足の境など）は毛の濃い色で柔らかく，外側の輪郭と口は濃い茶色．黒い耳先・足先の外側の縁も茶色にして，暗い画面の黒い背景に溶けないようにしている
- 半透明：半透明のドットは使わない（`art/build.py` が弾く）

ベースキャラを直すときは，これらの決まりを崩さない．ベースキャラの GIF を書き出す道具は置いていない．書き出すときは，色を減らさない（全ての刻みの色をそのまま並べたパレットを使う）．直したあとも，「構成」の手順で `sprites/` を作り直す．

`art/draw.py` は，ベースキャラに次を前提にする．

- GIF のコマの長さが100msの倍数で，計48刻みである
- 刻み0（目を閉じている）と刻み16は同じ姿勢で，目だけが違う
- 体が沈む刻み（`DY`）と，目を描く枠（`EYE_BOXES`）が，いまのベースキャラと同じである

## 役割とデザイン（確定）

### 本体と分身

- 昔話の「化け狐」にならい，葉っぱを「分身のしるし」とする．葉っぱの意味はこれだけにし，葉っぱの形と色は変えない
- 本体（メインの Claude）：葉っぱなし．これを標準の姿とする
- 分身（サブエージェント）：葉っぱあり．耳先・足先の黒は本体のまま残す（本体と分身の違いは葉っぱだけにするため）．働く役割は本体と同じ6つで，仕事を終えると本体と同じく眠る．分身も自分の分身を起動できるので，「見守る」もある．分身は質問を使えないので，分身の「呼ぶ」は許可待ちのときだけ
- 本体のコンテキストの使用率は，眠気で表す（「本体の眠気」）

### 分け方

- 役割は「いま何をしているか」で分け，ツール名から決める．エージェントの種類は使わない．分身の多くは汎用の種類で，種類で分けるとほとんど同じ姿になるため
- 役割は作業の種類（状態）だけにする．終了などの一瞬の出来事は役割にしない
- 表示は「最後に使ったツール」の役割を，次のツールまで続ける．読む・直すなどのツールは一瞬で終わり，待ち時間の大半はツールの合間（Claude が考えている時間）なので，ツールの実行中だけ役割を出すと，ほぼ「考える」になってしまう
- 役割は，一度出したら最低2秒続けてから切り替える（`hooks/den.ts` の `HOLD_MS`．2秒は仮の値で，「残り」の1で決める）．種類の違うツールが同時に呼ばれたときの，ちらつきを防ぐため
- 「呼ぶ」は，この2秒を待たずに，すぐ出す．ユーザーの返事か許可を待っていたツールが終わったら，最後に使ったツールの役割へ戻す
- どの役割にも当たらないツール（MCP のツールなど）は「考える」にする

役割は，働く6つと，働き終えた「眠る」の7つである．ツール名と役割の対応は `hooks/den.ts` の `ROLE_OF` が持つ．

| 役割 | きっかけ | ポーズ・小道具・動き |
| --- | --- | --- |
| 考える | 最初のツールの前，計画のツール，その他のツール | ベースキャラの待機アニメーション（そのまま） |
| 調べる | Read・Grep・Glob・WebSearch・WebFetch（手元のファイルもウェブも区別しない） | 布張りの本を自分へ向けて開いて読む（見えるのは表紙・裏表紙と背．表紙の縁に押し型，背に金の帯，上からページの小口がのぞく）．本がゆっくり上下し，視線が行を追う．ページをめくるときは本を大きく下げ，ページが弧を描いて返る |
| 書く | Write・Edit・NotebookEdit | 前に木の座卓（木目のある天板，手前の縁，脚）．天板に和紙を寝かせ，白い羽ペンを紙の左から右へ大きく走らせ，字の線が伸びる．頭も羽ペンを追って傾く．ときどき腕を大きく回して，コルク栓のガラスのインク壺に浸し，新しい紙の行頭で構える |
| 実行する | Bash・PowerShell | 前に木の座卓と，その上の銀色のノートパソコン（実物に近い縦横比．見えるのはふたの外側と蝶番，キーボード側の縁．座卓に影が落ちる．ふたに肉球のシール）．必死にカタカタ打つ：前足がふたの上へ交互に跳ね上がり（下りた前足はキーボードの上でふたに隠れる），打つたびに頭が揺れる（汗は出さない）．ときどき両方の前足をそろえて構え，Enter を押し込む（腕を大きく伸ばす動きはしない） |
| 見守る | 分身を起動するツール（Agent．旧名の Task も）．前で動く（起動した側が終わりを待つ）分身なら，終わるまで続く．裏で動く（待たない）分身なら，起動したキツネは自分の作業を続けるので，次のツールで別の役割に替わる．本体は，自分の作業を終えて分身を待つ間，ふたたび「見守る」になる | 分身の働きを，目を閉じて，お茶を飲みながら待つ．湯呑みは灰緑の釉薬の焼き物で，線の模様と素焼きの高台があり，口縁から緑茶が見える．両方の前足で両脇から包むように持つ．湯気がゆらゆら高く昇り，ときどき湯呑みを口まで持ち上げて一口飲む |
| 呼ぶ | 質問（AskUserQuestion．本体だけ），許可待ち（分身の許可待ちなら，その分身のキツネが呼ぶ） | こちらを向いて，胸の前で前足を小さく振って合図する（跳ねる・首をかしげるなどの大きな動きは不自然なのでしない）．相手に呼びかける役割なので，こちらを向くのが自然 |
| 眠る | 本体：返答を終え，働いている分身もいないとき．裏で分身が動いていれば「見守る」になる．分身：仕事を終えてから，パネルの列を外れるまで | 頭を垂れて眠る．ゆっくり息をして頭が上下する |

### 本体の眠気（コンテキストの使用率）

働く役割の絵に重ねる．目はベースキャラの閉じた目に戻すだけで，新しく描かない．境目は `hooks/den.ts` の `sleepinessOf` が持つ．いまの境目は仮の値で，「残り」の1で決める．

| 段階 | 使用率（仮） | 様子 |
| --- | --- | --- |
| 0 | 50%未満 | 眠気なし |
| 1 | 50%以上，70%未満 | まぶたが重く，長いまばたきが増える |
| 2 | 70%以上，85%未満 | 1に加えて，ときどき大きなあくびをする．口が見えるよう，本は大きく下げ，羽ペンは止めて脇へどけ，湯呑みは口まで持ち上げない．パソコンは下げられないので，打つのを止めるだけにする（口の大半はふたの陰に隠れる） |
| 3 | 85%以上 | 目を閉じて頭がゆっくり下がり（船をこぐ），ハッと起きて，あくびをする |

まぶたの重さとあくびは，役割の絵が描く．「考える」はベースキャラの絵をそのまま使うので，眠気が表れるのは，段階3で頭が下がることだけである．「見守る」はもともと目を閉じているので，段階1の絵は段階0と同じである．

会話の圧縮（古いやり取りを要約に置き換えること）で使用率が減ったら，減った後の使用率の段階へ戻る（50%を下回れば，すっきり目覚める）．分身には眠気をつけない．

### 見た目の決まり

- キャンバス：64×64ドットの正方形（ベースキャラと同じ）．整数倍に拡大して表示する
- 一貫性：どの役割も，ベースキャラの待機アニメーション（尻尾の揺れ・耳のぴくっ・体の沈み）をそのまま使う．役割が変えるのは，目の開け閉めと視線，前足，頭の傾き，小道具だけ
- 小道具：実物らしく描く（素材の色，光と陰，縁や継ぎ目などの細部）．キツネの横ではなく，前に置く．キツネが実際に使う向きに置き，見る人へ見せる向きにはしない（例：パソコンはふたの外側が見え，画面は見えない）
- 目：ベースキャラ自身の目を使う．閉じた目（刻み0），開いた目（刻み16．刻み0と同じ姿勢のまま目だけ開いている）とも，新しく描かない．開いた目は瞳・光のドットをすべて写し，形も高さもベースキャラどおりにする（視線は左右に1ドット動かすだけ）．作業中はときどきまばたきする
- 動き：作業の動き（タイピングなど）は，頑張っている感じが伝わるよう大きくする．ただし，合図などの身ぶり（呼ぶ）は控えめにする．汗や画面の光などの効果は足さない
- 葉っぱ（分身だけ）：遅れてついてくる動きは「考える」だけ．ほかの役割では頭に固定する．小道具などにも葉っぱの形を使わない（しるしの意味が薄れるため）

## 個体ごとの差

同じ役割でも，分身ごとに動きと色を少しずつ変える．分身の id から乱数の種を作り，次の値だけを変える．デザインそのものは変えない．

| 値 | 状態 |
| --- | --- |
| 揺れの位相（並んだキツネが同時に動かないようにする） | 実装済み．アニメーションの開始位置を，1周48刻みのどこかへずらす |
| 小道具の色 | 本の表紙だけ実装済み．元の色と，色相を回した5通りの，計6通りを `art/build.py` の `COVER_HUES` が持つ．シールは未実装 |
| まばたきの間隔 | 未実装．絵に焼き込まれているので，変えるには間隔ごとの絵が要る |
| 尻尾を振る周期 | 未実装．ベースキャラの動きなので，変えるには周期ごとのベースキャラが要る |

## 並べ方

本体と分身の数だけキツネを並べる．本体は常に先頭に置く．分身は加わった順に並べるが，「呼ぶ」の分身は本体の次へ寄せる（`hooks/den.ts` の `lined`）．キツネの列はパネルの幅で折り返すので，「呼ぶ」の分身が下の段に隠れると，待たせていることを見落とすためである．

- 絵は，何匹並んでも同じ大きさで描く．分身が現れたり消えたりするたびに本体の大きさが変わると，落ち着かないためである．小さく描くと，絵の下に書く一言（そのキツネが受けている指示）が収まらない．大量の分身を起動することは少ないので，大きめに描く
  - パネルが横に置かれているときは4倍（256ドット．ベースキャラの GIF と同じ）にする
  - パネルが入力欄の上に置かれているときは3倍（192ドット）にする．このパネルは背が低く，256ドットでは1匹でもスクロールバーが出る．パネルには1匹ぶんの絵と一言が収まる高さを頼む（`hooks/register.tsx` の `ROWS`）が，VS Code では，頼んでも256ドットが収まる高さにならない
- 1段に並ぶ数は決めず，パネルの幅に入るだけ横に並べて折り返し，各段を中央に寄せる．折り返して段が増えたときは，スクロールして見る
- 仕事を終えた分身は，すぐには外さない．すぐ消えると，短い仕事の分身は見る間もないためである．眠る姿で列に残し，ユーザーが次の依頼を送ったときに外す．完了の知らせや分身からの報告など，機械が入れた番（会話に入る1件の入力）では外さない（依頼の出どころで見分ける）
- 絵の下に，そのキツネがいま受けている指示を一言で書く（「リコーの調査」のように，何を受け持つかが分かる名詞句）．決まった文句は書かない．絵の幅に収まらない分は切る
  - 一言は，そのキツネに指示が届いたときにだけ付け替える．1匹のキツネは1つの指示の間に調べたり実行したりと色々なことをするが，その間，受けた指示は変わらないためである．何を頼まれているかを一言が，いま進めている作業を絵（役割）が表す
  - 分身：起動のときに付けられた仕事の名前（数語）をそのまま使う．名前が分からなければエージェントの種類を書く．起動した側が追加の指示を送ったら，その指示の要約に付け替える
  - 本体：ユーザーの依頼が届くたびに，その文から小さなモデル（`hooks/register.tsx` の `NAMER`）に付けさせる．依頼1件につき短い呼び出しが1回走り，その費用はセッションに計上される．依頼の受け付けは待たせず，新しい一言が届くまでは前の一言を出しておく．モデルが答えないか，役割を名付けずに依頼そのものに答えたときは，依頼の文をそのまま書く．スラッシュコマンドの入力からは付けない（指示の文ではないため）
    - 返事の1行目が，半角24字の幅（`hooks/register.tsx` の `LABEL_WIDTH`）を超えるか，句点・疑問符・感嘆符で終わるなら，依頼そのものに答えたとみなす

## 仕組み

### 表示

Claude Code の画面拡張（mod）として，閉じるまで出たままのパネルを開く．VS Code・デスクトップアプリ・モバイルのパネルに置ける絵はベクター画像（SVG）だけで，GIF は置けない．そこで役割ごとに，48刻みの絵を1枚のアニメーション SVG に焼いておき，パネルはそれを1匹につき1枚置く．絵を動かすのは SVG の中の CSS アニメーションで，プログラムが描き直すのは，状態（役割・一言・並び・眠気など）が変わったときだけである．

- 1枚の SVG は131,072文字まで．`art/build.py` は，キャンバスを四分木に割り，動く部分だけを細かく持ち，見せる刻みが同じドットを1つの層にまとめて，上限に収める．超えたら書き出しを止める
- 個体ごとの差は，読み込んだ SVG の文字列を置き換えて付ける（アニメーションの開始位置と，表紙の色）
- 動きを減らす設定の人には，デスクトップアプリがアニメーションを外して描く．そのときは刻み0の絵で止まる（`art/build.py` の `FROZEN`）．刻み0に見せない層だけを，素の状態で隠してある
- 端末はベクター画像を描けないので，絵は出さず，役割を文字で並べる．端末ではパネルが画面の一部を取るので，自動では開かず，`/fox` で開く
- VS Code・デスクトップアプリ・モバイルでは，セッションの開始時と，画面がセッションにつながった時に自動で開く．閉じたパネルは `/fox` で開き直す
- パネルは，開いても置かれないことがある．たとえば，描く画面がセッションにつながっていなければ，置かれないまま，つながるのを待つ．置かれなかったとき，`/fox` はその理由を伝える

### 拾う出来事

出来事のフックは眺めるだけで，結果には手を付けない．答えを返すのは，`/fox` のコマンドとパネルの描画だけである．

| 出来事 | すること |
| --- | --- |
| ツールの許可の判定（`tool.check`） | ツールを呼んだキツネの役割を，ツール名から決める．質問のツールなら「呼ぶ」にする．分身の中の呼び出しにはその分身の id が付き，本体の呼び出しには付かない．分身へ追加の指示を送るツールなら，宛先の分身の一言を付け替える |
| 許可待ち（`classic.PermissionRequest`） | 「呼ぶ」にする |
| ツールの終了・失敗・不許可（`classic.PostToolUse`・`classic.PostToolUseFailure`・`classic.PermissionDenied`） | 返事か許可を待っていたその呼び出しの「呼ぶ」を解く．許可待ちの出来事は呼び出しの id を持たないので，許可待ちは同じ名前のツールの1件ぶんを解く |
| 分身の開始（`classic.SubagentStart`） | 列に加え，仕事の名前をエージェントの一覧から読む |
| 分身の終了（`classic.SubagentStop`） | 眠らせて，列に残す |
| 依頼の提出（`prompt.submit`） | ユーザー自身が送った依頼なら，終えた分身を列から外し，本体の一言を付け替える |
| 依頼の受け取り（`classic.UserPromptSubmit`） | 本体を「考える」に戻す |
| 返答の終了（`classic.Stop`） | 本体を止める（働いている分身がいれば「見守る」，いなければ「眠る」）．終了の出来事を取りこぼした分身と，10分動いていない分身を，終えた扱いにする |
| 圧縮の終了（`classic.PostCompact`） | 眠気を測り直す |
| 会話の消去（`/clear`．`classic.SessionStart`） | 列を，本体1匹だけの最初の状態に戻す |

眠気は，本体がツールを使うとき・依頼を受け取ったとき・返答を終えたとき・圧縮を終えたときに，コンテキストの使用率から測り直す．

- ツールの呼び出しを `tool.call` で拾わないのは，そこにフックを掛けると，Claude Code のエンジン（会話とツールを動かす部分）がそのツールを裏へ回せなくなるためである
- 分身は，開始の出来事で列に加える．プラグインが会話の途中で読み込まれたために，開始の出来事を取りこぼした分身は，ツールの呼び出しを拾ったときに，エージェントの一覧に載っていれば加える．エンジン自身の内部の処理（圧縮など）も id を持つが，開始の出来事が無く，エージェントの一覧にも載らないので，列には加わらない

### 確かめ方

次の2つを，リポジトリの最上位で走らせる．

- `claude plugin validate plugins/fox`：プラグインの読み込みと型を確かめる
- `claude plugin test plugins/fox`：状態の決まりとパネルの描画を，`hooks/fox.test.tsx` で検査する

絵を変えない直しでは，直す前と後に `art/build.py` を走らせ，書き出したものが変わらないことを確かめる（直す前の `sprites/` とプレビューを，別の場所に取っておく）．描き方の整理なら `sprites/` とプレビューが，書き出しの仕組みの直しならプレビューが，1バイトも変わらない．書き出しの仕組みを直したら，書き出した SVG を読み戻して，全ての刻みと，アニメーションを外した絵を，元の絵と1ドットずつ突き合わせる．読み戻す道具は置いていないので，SVG の層とキーフレームから各刻みの絵を組み立てて比べる．

### 既知の限界

- ツールに許可を出したあとも，そのツールが終わるまで「呼ぶ」が続く．許可が出た瞬間に起きる出来事を，ツールの実行を妨げずに拾う方法が無い
- 役割が替わるたびに，アニメーションは最初から始まる（実機のパネルでは，ちらつきには見えない）
- 端末では絵を出さない
- クラウドセッション（Anthropic のクラウドで動かすセッション）のパネルは，デスクトップアプリでは出るが，モバイルでは出ない（iOS アプリで確かめた）．fox の側では直せない

2. 個体ごとの差の未実装分を足すかを決める．
